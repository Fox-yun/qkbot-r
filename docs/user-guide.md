# 配置与使用

容器安装、网络拓扑和升级见 [Podman 部署](deployment.md)。本文说明原生启动与管理功能。

## 原生启动


需要正在运行且支持 Milky 的协议端，以及兼容 Chat Completions 或 Responses API 的模型接口。编译需要稳定版 Rust；Windows 使用 MSVC C++ Build Tools。SQLite 随程序编译，无须独立安装。

```powershell
# 当前工作区已有工具链；其他环境可直接使用 cargo。
.\scripts\cargo.ps1 build --release --locked
.\target\release\qkbot.exe
```

首次运行会创建 `config.toml`，管理页面默认是 **http://127.0.0.1:3210**。用终端显示的一次性初始化码设置管理员密码，之后使用密码登录。密码至少 12 个字符、最多 1024 个 UTF-8 字节；服务端只保存带随机盐的 Argon2id 密码哈希，位于配置文件旁的 `.qkbot-admin/credentials.json`。请将该独立目录与配置文件一并妥善备份。

登录使用服务端会话和 `HttpOnly`、`SameSite=Strict` Cookie，前端不保存密码。会话最长 8 小时，30 分钟没有管理交互即失效，后台状态轮询不续期。配置应用、重置、遗忘及修改密码等敏感操作需要最近 5 分钟内验证过密码；修改密码会撤销其他登录会话。

在页面中配置模型接口、触发词、上下文和记忆、插件及预算。常用字段使用表单，其余字段可在高级 JSON 编辑器中修改。页面顶部和底部的“保存当前配置”只保存文件；点击“保存并应用”会正常停止旧机器人，再以新配置启动，管理页面和数据服务保持可用。页面区分已保存配置与运行中配置，已有会话的差异设置继续生效，调整全局默认不会覆盖它们。

模型接口支持“获取模型列表”：填写基础地址（例如 `https://服务商/v1`）或完整聊天地址后，服务端读取对应的 `/models` 接口，再从列表选择模型；获取成功会补全聊天接口路径。服务商不提供列表时仍可填写完整聊天地址并手动输入模型 ID。读取列表只在点击时进行，不会发送试聊请求或保存草稿。密钥框留空保留现有值，输入内容则在保存时替换；清除已保存密钥有单独按钮，保存前可撤销。环境变量密钥仍优先于文件配置。

在「配置管理 → 模型接口 → 请求协议」选择 **Chat Completions** 或 **Responses API**，填写该协议的完整接口地址并「保存并应用」。配置文件对应 `llm.protocol = "chat_completions"` / `"responses"`，地址分别使用 `llm.chat_completions_url` / `llm.responses_url`（通常以 `/v1/chat/completions` / `/v1/responses` 结尾）。旧配置未写协议时继续使用 Chat Completions；两个地址分别保留，模型和密钥共用，切换不会修改已有记忆、关系和预算。获取模型列表会补全当前协议地址；列表可访问不代表该模型支持两种协议，需要核对服务商能力。请求失败不会自动改用另一协议。

两种协议均用于聊天、图片输入、原生函数工具、个人记忆整理、自动摘要压缩和经验学习。Responses 使用非流式请求、`store=false` 和本地会话上下文；工具往返按 `call_id` 配对，携带当前轮所需的原始输出及加密推理项，不使用远端 `previous_response_id` 接续，也不把推理数据保存为聊天正文。函数保留现有可选参数语义（`strict=false`），截断或拒绝响应不执行工具。用量按 Responses 的 `input_tokens` / `output_tokens` 统计，额度规则与 Chat Completions 共用。协议实现参考 [OpenAI 迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)。向量检索仍使用独立的 Embeddings 配置。

在「群与好友」查看当前登录账号的 QQ 群和好友，按名称、备注或号码搜索，逐项开启或关闭 Bot。采用**黑名单机制，默认全部开启**，新加入的群和好友同样默认开启；只有关闭的对象被拦截。群内 AI 聊天按真实 @ 或关键词触发，其他插件使用各自的命令或事件入口。开关立即保存到 SQLite，无须重新应用配置，并按机器人账号、群 / 私聊和对象号码隔离。关闭后停止该会话的新消息处理、记忆学习、回复与工具操作；已存历史和记忆保留，已经提交给 QQ 的网络请求无法撤回。重新开启不会恢复已失效的聊天回复或工具确认；已创建的提醒会暂停，开启后继续处理到期提醒。列表按需加载，可手动刷新；即使聊天服务尚未配置好，只要 QQ / Milky 已连接，仍可管理开关。

每行的「插件」按钮可分别关闭该群或好友的原生、NoneBot 插件，取消勾选即时生效，同样采用黑名单机制。全局启用项在「配置管理」勾选后保存并应用；戳一戳、轮盘禁言和六个 NoneBot 预设默认全局关闭。会话勾选不能启用一个全局已关闭的插件。

每行另有「自动接话」开关，**默认关闭，必须为每个群或好友单独开启**，没有全局开启入口。开启后，普通消息也可唤醒 AI，由模型结合对话决定回复或保持安静；不额外调用一次模型来判断是否接话。群聊按群开启，切换共享上下文或按成员隔离模式都沿用该群的开关；机器人账号、群和私聊分别保存，新增群和好友不会自动继承。关闭时群聊继续按 @、关键词及已开启的引用回复触发，私聊仍可直接对话。Bot、AI 插件、暂停状态和预算限制继续生效，开启不保证每条消息都回复，并可能增加模型用量。

各聊天的自动接话开关立即保存到数据库，重启后保留，无须应用配置。切换时取消该聊天旧设置下尚未完成的回复与工具确认，保留历史、摘要和长期记忆；已提交的 QQ 请求无法撤回。列表离线时可关闭自动接话，开启必须重新验证当前 QQ 账号和联系人归属。

在「配置管理 → 自动接话」调整全局参与策略和参数，保存并应用后生效。配置文件对应 `[plugins.ai.auto_reply]`，只影响已经逐项开启自动接话的群或好友，不会自动开启任何聊天。策略提示词用于调整何时自然参与，例如更克制或偏好接续闲聊；静默协议、工具权限、撤回处理和明确触发优先级由程序固定处理，不能由策略覆盖。

策略只注入自动接话请求，正常 @、关键词或有效引用提问不会加载它。策略与人设、当前消息共同计入该会话的输入预算；使用较长策略时应提高输入预算，为历史、摘要和记忆留出空间，程序不会静默截断策略或扩大预算。应用配置会重新启动聊天运行时，并清空已记录的自动接话冷却。

编辑策略、默认人设或输入预算时，页面会自动显示保守占用估算，并在接近或超过预算时提醒。估算包含固定规则、策略与所选人设，当前消息、历史、摘要、记忆和工具还需占用剩余空间；它不是模型的精确 token 数。会话单独覆盖人设或输入预算时，应以该会话的设置为准。提示不会阻止保存，也不会自动调整内容或预算。

默认连续发言等待 1.5 秒合并，最长等待 5 秒，每批最多 8 条；使用当前会话的模型、人设、历史、摘要、记忆和识图设置，不另设 30 秒上下文截断。主动回复后，同一群或好友默认冷却 30 秒；保持安静不占用此冷却。真实 @、关键词和有效的引用触发优先，取消尚未发送的自动回复。批次默认超过 120 秒不再发送。自动接话可使用获准的读取、搜索和回复工具；创建、删除提醒等写入操作须通过明确触发处理，避免把多人聊天误当作最后一位发言者的操作授权。

| 自动接话字段 | 默认值 | 可配置范围 |
| --- | --- | --- |
| `prompt` | 结合上下文自然参与、不抢答、不重复 | 去除首尾空白后 1–2000 个字符 |
| `cooldown_seconds` | 30 秒 | 0–3600 秒；0 表示取消额外自动接话冷却 |
| `debounce_ms` | 1500 毫秒 | 100–10000 毫秒 |
| `max_wait_ms` | 5000 毫秒 | 100–30000 毫秒，且不小于 `debounce_ms` |
| `max_messages` | 8 条 | 1–32 条 |
| `max_age_seconds` | 120 秒 | 5–600 秒，且不短于 `max_wait_ms` |

以上参数即使在 AI 全局关闭时也会校验；每会话发送额度、普通 AI 冷却和总预算仍然生效。

轮盘禁言、戳一戳等十二项原生功能直接由 Rust 运行，无需开启 NoneBot。启用 NoneBot 前需设置至少 32 字节的独立连接令牌；缺少令牌会阻止整份配置应用，旧运行实例保持原配置。管理页会持续区分「已保存待应用」与「已应用」，显示应用阻塞原因，以及各插件在当前运行实例中的实际启用状态。

也可手动编辑 `config.toml`，设置 `[milky]` 和 `[llm]` 后启动：

```powershell
$env:QKBOT_API_KEY = "你的模型密钥"
# $env:QKBOT_MILKY_TOKEN = "你的 Milky token"
.\target\release\qkbot.exe --config config.toml --check
.\target\release\qkbot.exe --config config.toml
```

Linux / macOS 使用 `cargo build --release --locked` 和 `./target/release/qkbot`。不需要 Node.js 运行机器人；Node 只用于可选的本地性能冒烟脚本。

`--check` 只校验配置，不连接 QQ 或模型。环境变量覆盖文件中的密钥；相对数据库路径按配置文件目录解析。日志输出到 stderr，可交给服务管理器轮转。退出使用 Ctrl+C，Unix 也处理 SIGTERM。

## QQ 扫码登录

使用同时支持 Milky 和登录管理接口的 **LLBot（LuckyLilliaBot）**。先按 [LLBot 官方说明](https://luckylillia.com/guide/config) 安装并完成所选运行模式的前置配置 / 授权。LLBot 是独立的 QQ 协议端，Rust 程序不包含 QQ 客户端或签名服务。

1. 在 LLBot 中启用 Milky HTTP / WebSocket 服务，常见地址为 `http://127.0.0.1:3010`。
2. 在本项目管理页填入 Milky 地址和访问令牌；QQ 登录管理填入 LLBot WebUI 地址（常见为 `http://127.0.0.1:3080`）及其 **WebUI 密码**，保存配置。
3. 在“QQ 登录”中获取二维码，用手机 QQ 扫码并确认。页面轮询登录状态，机器人自动等待并连接 Milky；二维码失效时手动刷新。

管理员密码、LLBot WebUI 密码、Milky 访问令牌和 LLBot 前置授权 `auth_token` 用途不同。这里代理二维码与登录状态，不收集 QQ 密码，也不管理签名授权。接口按 [LLBot v8.3.2 源码契约](https://github.com/LLOneBot/LuckyLilliaBot/blob/dc2b2b90092ef0f571b5546878288b83fff1e436/src/webui/BE/routes/login.ts) 实现；其他 Milky 协议端仍能接入聊天，内嵌扫码需要提供相应管理接口适配。

QQ 状态在服务端缓存 3 秒，同时到达的状态请求共用一次上游查询；二维码只允许一次在途获取。认证失败后暂停访问 LLBot，修改登录配置或明确手动重试后再尝试；临时网络故障由页面退避查询。改变配置会使旧请求结果失效。

配置页面不会返回已有密钥；分别选择保留、替换或清空。环境变量 `QKBOT_API_KEY`、`QKBOT_MILKY_TOKEN`、`QKBOT_LLBOT_TOKEN` 优先于文件配置，页面会标明来源，环境变量值不会写回配置文件。首次初始化码也可由至少 32 字节的 `QKBOT_ADMIN_TOKEN` 提供，设置密码后不再用于认证。保存配置使用同目录原子替换，并检测版本冲突；会规范化 TOML 格式，不保留原文件注释。后台读取已验证的内存快照；明确刷新配置时才重新读取外部编辑。

管理端默认仅监听本机。远程访问可使用 SSH 端口转发；需要公开服务时，将它放在 HTTPS 反向代理后并设置 `web.secure_cookie = true`。该开关明确控制 Cookie 的 `Secure` 属性，不根据请求头猜测。`web.enabled`、`web.listen`、`web.secure_cookie` 和日志过滤级别需要重启整个程序；数据库路径 `app.database` 与数据库队列容量 `limits.database_queue` 也必须重启才能应用。其他配置可在页面保存后应用。`web.enabled = false` 可关闭管理页。

## 配置取舍

`[plugins.ai.defaults]` 是全局默认，“会话”页面保存各会话的差异设置。工具能力及部署级队列和调用配额在管理页或配置文件中调整，保存并应用后生效；数据库队列容量需要重启程序。

`reply_to_bot = true` 默认开启“回复机器人消息时触发 AI”：在群内引用回复当前机器人账号发出的消息，无需再次 @ 或输入关键词。管理页的全局配置和会话设置均可调整；关闭后仍保留私聊、@ 和关键词触发。原生插件命令与 NoneBot 已接管的交互优先处理；引用其他成员、转发内部的引用或机器人自身事件不会因此触发。

触发只会唤醒 AI，不强制发送回复。模型会在同一次请求中结合当前消息、近期对话和引用决定是否有必要回应；没有新信息的应和、重复复述或机器人互相接话等可静默结束，不发送占位文字或“不回复”提示，也不新增一轮判断请求。此行为同样适用于关闭工具调用的会话；后续有新问题时仍可正常回复。原生插件命令仍按各自规则执行。

引用目标按机器人账号、聊天类型、群／好友和消息序号确认，优先使用本地记录，缺失时最多并发两次、每次两秒向 Milky 补查。查询失败或繁忙时不增加触发，原有 @ 等触发仍有效；同会话的后续消息按顺序处理。触发 AI 后附加该条引用的至多 1000 字文字；开启识图时也读取其中的直接图片。因此，@ 机器人并引用其他成员的消息时，引用文字和图片会一并提供。不恢复旧会话、不切换到原提问者的记忆，也不将引用内容作为当前用户的事实证据；已遗忘来源不会重新注入，无法读取的内容会明确标记。

允许模型使用的工具从实际注册表自动载入，以勾选列表配置，无须手写工具名；列表显示说明、所属插件与操作类型。全局勾选并启用对应插件、保存并应用后生效；会话只能进一步缩小允许范围，取消全部勾选即禁用全部模型工具。升级后失效的已选工具会保留显示，便于取消和修复配置。

人设在配置页和会话页直接从列表选择。内置五套成年男性角色：**雄小鬼**（默认，爱斗嘴、好胜、嘴硬心软）、清朗青年（坦率有活力）、温柔学长（耐心有分寸）、理性搭档（简洁、冷幽默）、沉稳前辈（务实、松弛）。配置页可预览完整模板，编辑或另存自定义人设，无须填写 JSON；同名自定义内容优先于内置模板。全局配置保存并应用后生效，会话选择单独保存；切换人设保留历史和记忆。

在“记忆与上下文”页选择已保存、已应用的人设，点击“应用到全部群聊”，确认账号与群数量后立即生效。后台以提交时刷新得到的 QQ 群列表为准，一次更新该账号全部现有群的共享及成员隔离会话，同时保存这些群以后新建会话的人设。好友、其他账号及全局默认不变；之后新加入的群仍使用全局默认。各会话的其他设置、历史、摘要和长期记忆保留，旧人设未完成的回复取消。操作按请求编号去重，网络中断后可查询结果；仍可在会话页单独切换某个会话。

提示词结构参考 [dafeiyu-bot 的 QQPersona / QQPersonality](https://github.com/SAKURAfan1023/dafeiyu-bot/blob/282f7d0c7444d2c6ef4f03a5a77e72862c844f27/Sources/BotCore/QQPersona.swift)，模板正文为小鱼原创：宿主身份、权限和能力规则 → 本轮选定的角色与表达习惯 → 真实会话上下文。历史中的旧性格不覆盖当前选择；人设不会改变工具权限、事实归属或上下文隔离。每轮只注入当前一套模板，不增加模型调用或外部依赖。

`mode` 是新群的初始模式；已有群在“会话”页面切换模式，避免修改默认值时意外恢复旧会话。关闭记忆写入或暂停期间的新消息不会被标记为自动学习来源。

`[plugins.ai].global_memory_shared = true` 默认开启“全域长期记忆共享”，也可在“配置管理 → 上下文与记忆”调整后保存并应用。同一机器人账号内，同一 QQ 用户在所有群聊和私聊中共用长期记忆；群内按用户隔离的模式也使用这份记忆。机器人会在群聊中使用该用户先前在私聊形成的记忆，反向也一样。不同 QQ 用户和不同机器人账号仍独立，姓名和群名片只作显示。近期聊天记录、摘要、人设和会话设置继续按原会话管理。

关闭全域共享后，记忆只在其来源会话中检索和维护；重新开启后恢复跨会话共享。切换开关不会删除、复制或搬迁已有长期记忆，已有各会话记录也纳入共享范围，仍保留来源和证据。应用开关变更时会重置短期上下文与摘要，使旧任务失效，避免关闭后仍从摘要引用跨会话内容；原始消息按原保留期保存。“记忆与上下文”页会显示当前记忆范围，可按人物 QQ 号筛选；短期上下文重置不会清空共享记忆。

群聊发言会保存消息当时的群名片和 QQ 昵称，模型优先用群名片称呼用户，缺失时回退到昵称或 QQ 号。名称只作显示，身份、权限、记忆和证据仍绑定 QQ 号；同名、改名及跨群名片不会合并用户。名称来自事件自带的成员信息，不额外拉取成员目录；老消息无需补查，原始正文保持不变。

升级时若配置仍包含旧 `[access]` 白名单，程序会拒绝加载，避免无提示扩大聊天范围。请先核对黑名单、明确接受“未关闭的会话默认开启”后，再手动移除旧配置段；正常黑名单配置不受影响。

| --- | ---: |
| 模型 HTTP 并发 / 后台整理并发 | 2 / 1 |
| 全局 / 每会话待处理聊天 | 32 / 4 |
| 输入估算预算 / 输出上限 | 6000 / 800 |

预算使用保守的 UTF-8 字节估算，**不是模型 tokenizer 的精确计数**。工具定义、调用和结果都计入输入预算；问题本身超限会明确拒绝。普通聊天通常只请求模型一次，当前无隐藏重试。

`max_memories_per_conversation` 控制磁盘中的长期记忆容量：全域共享时按同一机器人账号内每个 QQ 用户计，关闭时按来源会话计；`memory_recall_limit` / `memory_recall_budget` 控制一次取回多少内容，提高容量不会把全部记忆装进上下文。降低容量不会删除既有记忆。输入预算可调至 262144、输出上限至 32768、历史至 4096 条；实际可用量仍取决于所选模型、消息发送限制与总输入预算。复杂工具任务可提高 `max_model_calls`、`max_tool_calls`、`max_http_attempts` 和整轮超时，保留有界执行及最终回答机会。

关键词检索是首版的低占用选择，换一种完全不同的说法可能漏召回。先收集真实漏召回案例，再决定是否加向量检索。群内 `user` 模式只隔离上下文，回复仍发到群里。

## 引用与 @ 回复

`reply_message` 让模型把引用、@ 和正文合并为本轮唯一的最终回复，例如引用某条可见消息回答问题，同时 @ 相关成员。每条回复最多引用一条消息；@ 去重后最多三人，仅限群聊。普通回应仍可直接输出文字；本轮回复不额外请求确认，业务工具按各自的确认策略执行。

新配置默认允许 `reply_message`，管理页将其显示为 AI 插件的“本轮回复”工具。已有配置若显式填写了 `allowed_tools`，升级不会自动扩大名单：管理员需在全局工具列表勾选并保存、应用；继承全局设置的会话随后可使用，已有显式会话名单仍须按需勾选。模型接口还需开启原生工具调用。

宿主只为本轮实际可见的当前消息、近期上下文、当前明确引用的消息，以及这些来源中的发言者和当前消息真实 @ 的对象提供引用标识。模型不能用正文中的昵称或 QQ 号自行指定目标，也不能跨机器人账号、群／私聊或逻辑会话查找历史；当前明确引用按当前聊天验证后可使用。已遗忘、因预算裁剪而未向本轮模型提供或其他已失效的目标不能用于引用或 @。首版不提供 `get_recent_messages`、`get_message` 或 `find_member` 工具来查询新目标。

## 图片识别

`[llm].vision = true` 默认开启图片识别，管理页“模型接口”中的“启用图片识别”开关保存并应用后生效；模型及服务商接口也需支持视觉输入。机器人读取**当前触发 AI 的消息及其明确引用的那条消息中直接发送的图片**，并将处理后的图片与本轮文字一并交给模型，同时标明图片来自当前消息还是引用消息。两处合计每轮最多尝试四张，优先当前消息，再按顺序读取引用图片，共享下载时限。单图下载上限为 8 MiB；超出数量、尺寸或大小限制、无法下载或解析的图片会按未读取处理，继续使用可用文字；关闭开关后只按文字处理。

图片按比例缩至最长边不超过 1024 像素，并占用本轮输入预算，实际提供数量可能少于四张；预算不足时优先保留当前文字和工具结果，并提示未提供的图片。常用多图问题可在会话设置中提高输入预算。图像额度是估算值，实际消耗以接口返回用量为准。动图仅读取首帧。

普通群聊背景消息不会触发图片下载，未被当前消息明确引用的历史图片和合并转发内部的图片也不会读取；引用只展开一层。引用图片通过 Milky 按完整消息键获取，并检查撤回与遗忘状态。图片文件及编码数据仅用于当前轮次，不持久保存到聊天历史或长期记忆；后续轮次只能看到文字上下文，再次明确引用原图片消息时会重新读取。

## 会话与记忆管理

“会话”页面按机器人、群或好友、用户和模式筛选，查看摘要和上下文数量，调整人设、预算、历史长度、工具、记忆读写和摘要开关，也可暂停、恢复或放行一次触发。重置会清空活跃上下文与摘要，保留长期记忆；切换群模式创建隔离的新会话版本。

“记忆”页面支持分页检索、查看证据与关联原文、人工新增和编辑、启用或停用。人工记录默认锁定，自动整理不会改写人工或锁定记录。停用和到期只排除召回，保留记录及来源，也继续计入存储容量。

自动整理采用日常记录方式，饮食娱乐、近况心情、活动经历、计划和项目小进展都可以纳入记忆，一次提及即可。临时状态建议保留 7–30 天、普通事件 30–90 天，重要经历和稳定偏好可长期保存；一次性评价不会被要求归纳为长期偏好。每批最多提取 16 项，后台整理输入估算预算 `memory_input_budget` 默认 8000，输出预算默认 3200；普通聊天的输入预算仍独立默认为 6000。保留原文证据与人物归属检查，新规则不会自动重新提取已处理的历史消息。

人物画像也来自本人原文：自述的身份和生活背景记为“人物背景”，兴趣、习惯和交流偏好记为偏好。对表达方式的“聊天观察”至少需要同一人两条不同消息作为证据，并注明依据，保留 7–30 天；不凭聊天推断外貌、精神诊断或绝对性格。这些记录属于用户记忆，不会改写机器人的人设。

从机器人记忆中遗忘使用“预览影响 → 确认”流程，可单条或批量操作。预览包含受共同来源影响的派生记忆；确认后撤销相关历史来源，清空受影响会话的摘要与活跃上下文，防止旧任务重新学回。本地原始消息按保留期清理，遗忘不等同于立即擦除原文，也不会删除 QQ 消息、远端模型记录或备份。此操作需要重新验证密码，确认凭据与当前管理员会话绑定，5 分钟有效。写操作带幂等请求 ID，超时后可以查询已有结果。

关闭自动记忆写入不影响人工维护；摘要也有独立开关。关闭摘要同时停止生成和注入，近期上下文按历史长度读取原始消息，长期事实仍可独立学习。再次开启时，从仍保留的原文补齐摘要进度，不重复提取已处理事实。

空闲会话即使只有少量消息，也会尝试从符合学习条件的完整消息中提炼长期事实，不必等待近期上下文被压缩。整理仍受后台并发和每小时调用额度约束，按会话轮转并对失败退避；一个异常会话不会堵住其他会话。自动提炼是后台工作，聊天中说“记住”不代表已经可靠写入，可在记忆页核对或人工保存。

自动上下文压缩保留原有条数和空闲触发，并增加输入压力触发：裁剪前文字输入或尚未整理原文的保守估算达到普通输入预算的 70% 时，后台以 50% 为目标选择压缩边界。默认至少保留最近 16 条原文，保留完整问答轮次；不超过会话的 `recent_messages` 上限。压缩间隔至少 180 秒，个人事实提炼不受此冷却限制。前台有对话或后台额度不可用时延期，最终请求仍有硬预算限制；50% 是规划目标，最近原文下限、当前问题和工具等固定内容可能使其无法达到。

`plugins.ai.compaction.summary_budget` 独立控制摘要的双 JSON 转义 UTF-8 字节预算，默认 2048；不再固定为整理输入的四分之一。整理输入过小时仍限制到能再次读取摘要并容纳来源的范围。输入足够时采用结构化话题摘要，记录参与者 QQ、结论、未完成事项、关键原文和来源；压缩修复保留未完成事项及关键原文，并核验人物和来源。已有纯文字摘要继续兼容；正文不因压缩立即删除，按原始消息保留期处理。

优先对话效果的部署配置：普通输入 `131072`、输出 `9216`、最近消息 `96`；个人事实召回 `8192`／最多 `12` 条、人物关系注入 `4096`；跨会话接续 `24000`（其中背景最多 `18000`）；经验笔记额外注入 `12000`。后台个人整理输入／输出 `32768`／`6144`，话题摘要 `8192`；经验学习输入／输出 `65536`／`4096`。输入采用保守字节估算，输出为模型 token 上限。个人资料和接续包含在普通输入内，笔记额外计入，因此开启笔记时最终输入估算上限为 `143072`，不能把所有分区相加后再加普通输入。这是一组显式部署值，通用默认值仍适用于较小模型。

后台提炼和旧摘要修复均接受裸 JSON 或完整单个 JSON 代码块；代码块只去掉外层包装，内部字段、人物身份和原文证据仍严格校验。截断响应、混入解释、多个代码块或无效证据不会被自动补全或部分保存，失败批次也不会推进处理游标。解析错误日志只记录类型与位置，不包含模型返回正文；模型调用计数增加不等于已写入，确认结果应查看自动记忆及其来源证据。

### 历史记忆重整

管理员可以在完整备份后，通过维护命令重新整理数据库中仍保留的原文，补充日常记忆和有证据的人物画像。命令与备份步骤见[部署说明](deployment.md#91-历史记忆重整)。首次运行会冻结任务的来源窗口；使用同一个任务名可续跑，后续新消息不会加入该任务。

回扫限于当前机器人账号、当前会话版本和当前有效聊天范围，并要求会话未暂停、开启记忆写入。只有当时已标为可学习、未撤回或遗忘的真人原文可作为来源，已处理和未处理的符合条件消息都可纳入。原文已因保留期清理、属于旧会话版本，或当时没有学习资格的消息不能借回扫补回。

重整只新增尚未覆盖的记忆。去重参考包含同一会话、同一人物的全部既有记录，包括人工、锁定、停用和过期记录；这些旧记录不会被修改、删除或重新启用。临时记忆按证据原消息的时间计算到期日，已经到期的候选不会因本次重整重新获得保留期。原有摘要、正常整理游标、机器人设定和发送记录保持不变；记忆容量限制仍然适用。

## 学习笔记

在“配置管理 → 学习笔记”开启并保存应用。模块默认关闭；开启后从同一机器人账号下、允许记忆写入的有效群会话中新收到的真人消息提炼交流经验、纠错和术语，不自动回扫旧历史，不从私聊取材。未触发机器人的群背景消息还须原本已开启“学习群内背景消息”。通用笔记在同一账号的群聊间共享，群特定笔记只在原群召回，不同机器人账号相互隔离。个人偏好和身份仍由 QQ 个人记忆管理。

学习复用聊天模型，但使用独立额度：默认每小时最多 4 次、滚动 24 小时最多 24 次，两次尝试至少间隔 900 秒。每批最多 40 条消息、6 项修改；整份当前笔记默认最多 2000 字符。管理员可调整学习规则提示词、批次大小、间隔、容量、输入估算预算和输出上限。失败或额度耗尽时继续使用已有笔记，后台没有空闲模型容量时延期。

“学习笔记”页查看当前账号的笔记、来源与版本历史，支持人工新增、编辑、锁定、删除和回滚。锁定只保护内容免于学习模型修改，不保证每轮注入。并发变更会要求刷新后重试；回滚同样经过容量和来源校验，已撤回或永久遗忘的来源不能借回滚恢复。来源撤销会清除相关笔记及其历史，并使受影响账号的旧对话上下文失效。

每个账号最多保留 128 条有效笔记、512 条记录（含已删除条目），每条最多保留 32 个历史版本。新增后超过记录上限时清理最旧已删除条目及其历史，已清理的条目无法回滚。

笔记只作为参考资料提供给已开启记忆读取的群聊，不能修改人设、权限或宿主规则。“启用笔记向量召回”（`plugins.ai.learning.semantic_recall`）默认开启，须同时启用学习笔记和全局 Embedding 服务才会发出向量请求。召回按向量与文字相关性排序；关闭向量召回、尚未建立索引或服务不可用时，回退文字匹配和最近笔记。“每轮最多召回笔记数”（`recall_limit`）默认 8 条，可调为 1–128 条，所有召回和回退方式共用这个完整条目上限。

笔记复用已有 Embedding 接口，保存独立的笔记向量缓存，后台每轮最多建立 1 条索引；模型或维度变化后自动重建。笔记修改、删除、来源撤回或遗忘会清理相应缓存。笔记向量请求独立限制为每小时 120 次，与学习模型默认每小时 4 次、滚动 24 小时 24 次的额度分别计算。读取不调用学习整理模型；启用语义召回会产生向量请求用量，选中的笔记也会增加聊天模型输入用量。

聊天时笔记有默认 **12,000** 的独立输入额度，由管理员通过 `plugins.ai.learning.injection_budget` 调整（0–64,000；0 暂停注入但不停止学习）。先按原聊天预算组装问题、历史、个人记忆和工具协议，再按相关性、召回条数和独立额度筛选完整笔记，互不挤占；最终请求上限为原聊天输入预算加笔记额度。这里的估算含 UTF-8/JSON 转义与消息封装，并非精确 tokenizer；仍需使两项预算之和适合所选模型。

## 聊天指令

```text
/bot confirm TOKEN
/bot reject TOKEN

/clock
/remind add 600 喝水
/remind list
/remind cancel ID
```

提醒插件默认关闭。启用 `[plugins.reminder].enabled` 后，普通 `/remind` 指令直接执行业务。新配置的 AI 工具允许列表已包含 `reminder_list`、`reminder_create`、`reminder_cancel`；已有显式列表须勾选这三个工具并保存、应用，会话单独限制的工具列表也需允许。

将 `llm_writes_require_confirmation` 设为 `false`（新配置默认值），即可说“小鱼，提醒我20分钟后吃饭”，由 AI 直接创建，无需再次确认。时间从收到这条消息时起算；提醒仅属于当前用户、当前聊天，群内提醒公开。“取消刚才吃饭的提醒”会先查询本人本会话的提醒，再按真实 ID 取消；多个候选无法确定时会询问取消哪一条。提醒时间范围为 1 分钟至 30 天，每人每会话最多 10 条待处理提醒；已开始发送的提醒不能取消。

已有配置中的显式 `true` 会保留：此模式下 AI 创建和取消仍需本人在原聊天发送 `/bot confirm TOKEN`，5 分钟内有效；确认只执行已固定的时间、内容或目标，不阻塞聊天。管理页“AI 创建和取消提醒需要再次确认”开关控制同一选项。

已创建的提醒可跨重启保留，未确认的请求在重启后失效。收到离线或换号事件后，暂停新发送与引用读取；原账号重新验证成功后，确定尚未提交的提醒恢复待发送，发送结果未知的提醒仍不自动重发。

到期领取与异常恢复均只处理当前已验证账号的提醒，每次领取一条并关联发送账本；数据库回写中断后，可区分尚未提交、确定完成和结果未知。其他账号的待办保持等待，不会被当前账号消耗。联系人列表暂不可用时，页面保留上次读取的账号列表供关闭 Bot，开启仍须恢复连接后重新核验；旧协议缺少群备注字段时显示为空。

## 扩展插件

在 `src/plugins/` 编写 `Plugin` 实现，在 `plugins/mod.rs` 显式装配。普通命令与模型工具复用业务方法；要提供给模型，实现 `Tool` 并注册，还须配置工具允许列表。新增工具无需修改 AI 主循环。`Plugin::accepts` 管命令和事件范围，`Tool::permits` 独立约束工具范围；本地 Rust 插件属于可信代码。

数据库迁移使用 `Store::migrate(plugin_id, version, sql)`，按插件记录校验和。数据库由专用线程持有；事务内只做短小的本地工作。所有发送使用 `Host::send`，网络结果未知时记账，不自动重发。

详细说明见 [架构与边界](architecture.md)。


### 近期话题接续与个人学习状态（2026-10-26）

「上下文与知识 → 对话接续」现在可以预览尚未形成机器人问答的话题。默认会按当前用户的 QQ 召回近期本人发言、必要的引用和群聊前后文；即使没有触发机器人，也可在切到本人私聊后接上讨论。消息需要已被允许记录，仍受时间、条数、预算、会话模式、来源权限和撤回状态限制。

在配置中设置 `plugins.ai.context.cross_scene`：默认 `private_followup` 允许群聊接到本人私聊；`same_scope` 仅原场景；`shared` 显式允许同一用户跨群及私聊共享。`global_memory_shared=true` 决定长期知识检索域，不会绕过这一使用范围。旧配置省略新字段时采用默认策略；需要保留旧跨群行为，应明确选择 `shared`。`include_unanswered=false` 可以只保留完整问答接续。

自动个人记忆提炼会独立处理每条候选。有效项可以先保存，错误项有固定原因码；摘要失败不会丢掉有效事实。失败的个人提炼保留原消息范围，间隔至少 60 秒重试，总计最多三次，且不会重复写入相同结果。三次后显示“待核对”，继续处理后续消息；可在个人记忆中核对，并按既有重建流程重新处理仍可用的来源。摘要保留自己的游标单独重试。被撤回、遗忘、改变身份或权限的来源不能因重试恢复。

管理页展示的是来源预览及有限的近期整理诊断，不代表每轮模型实际读取了所有记录。引用与角色扮演的语义判断仍可能有误，可通过证据核对和纠正处理。


### 个人记忆与关系

进入「上下文与知识 → 人物与关系」，输入用户 QQ，可聚合查看该人的个人事实，以及当前角色的称呼、互动偏好、边界和近期直接交流。个人事实的证据、编辑和永久遗忘仍在「个人记忆」页管理。关系记录可以单独纠正、删除，或重置当前角色的关系；这些操作不删除原始聊天和个人事实。重置后，已在处理的旧消息不会重新建立旧关系。

关系默认开启，按机器人账号、用户 QQ 和稳定角色 ID 分开保存。各群的人设文案和风格可以不同，默认都使用 `default` 角色；只有明确需要独立角色时才修改 `plugins.ai.personal.character_id`。不同角色的关系分别保留，人物事实仍属于同一机器人与用户。

熟悉程度来自已确认的直接交流，同一场景每天最多计入一次，按最近 64 条交流记录中的不同日期分为少量、多个日期、比较熟悉和长期熟识几档，并附上最近一次和最早可追溯交流大约在几天前；不因纠正、拒绝或离线降低，久未交流只提示可以自然寒暄。每轮最多注入 4 条边界、最新 1 条称呼和 4 条近期交流风格，冲突时以较新的为准。内置人设的「熟悉程度」一节说明初识、熟悉和久别后的语气变化；使用同名自定义人设时，需要自行补充类似说明。称呼、偏好和边界由原有后台个人提炼任务从本人明确表达中学习，不额外调用逐消息模型。管理纠正会标注来源，来源撤回或遗忘后不能恢复。模块停用后可继续人工管理已有关系。

`plugins.ai.personal.injection_budget` 默认 2400，范围 0–8000，计入普通输入预算；0 暂停注入。关系资料也遵守 `plugins.ai.context.cross_scene`：默认私聊称呼不会进入群聊。后台 `memory_input_budget` 低于 3712 时，仅请求原有事实提炼；使用默认 8000 可同时提炼关系偏好。此版没有好感分，关系不会授予额外工具或私人信息读取权限。

需要本人在群里延续自己的私聊时，将 `plugins.ai.context.cross_scene` 设为 `shared`。宿主以实际发言者 QQ 召回该人的私聊事实、关系资料和近期对话；不限于天气问题。正文声称的身份、昵称、引用和 @ 不改变召回主体。多人自动接话批次不据最后一位发言者读取其私人资料。“我家天气”“我老家”等问法同时检索居住、家乡等地点事实，仍需事实属于本人且来源有效；存在多个地点或缺乏地点时应由模型结合上下文确认。

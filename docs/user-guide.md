# 配置与使用

容器安装、网络拓扑和升级见 [Podman 部署](deployment.md)。本文说明原生启动与管理功能。

## 原生启动


需要正在运行且支持 Milky 的协议端，以及兼容 Chat Completions 的模型接口。编译需要稳定版 Rust；Windows 使用 MSVC C++ Build Tools。SQLite 随程序编译，无须独立安装。

```powershell
# 当前工作区已有工具链；其他环境可直接使用 cargo。
.\scripts\cargo.ps1 build --release --locked
.\target\release\qkbot.exe
```

首次运行会创建 `config.toml`，管理页面默认是 **http://127.0.0.1:3210**。用终端显示的一次性初始化码设置管理员密码，之后使用密码登录。密码至少 12 个字符、最多 1024 个 UTF-8 字节；服务端只保存带随机盐的 Argon2id 密码哈希，位于配置文件旁的 `.qkbot-admin/credentials.json`。请将该独立目录与配置文件一并妥善备份。

登录使用服务端会话和 `HttpOnly`、`SameSite=Strict` Cookie，前端不保存密码。会话最长 8 小时，30 分钟没有管理交互即失效，后台状态轮询不续期。配置应用、重置、遗忘及修改密码等敏感操作需要最近 5 分钟内验证过密码；修改密码会撤销其他登录会话。

在页面中配置模型接口、触发词、上下文和记忆、插件及预算。常用字段使用表单，其余字段可在高级 JSON 编辑器中修改。页面顶部和底部的“保存当前配置”只保存文件；点击“保存并应用”会正常停止旧机器人，再以新配置启动，管理页面和数据服务保持可用。页面区分已保存配置与运行中配置，已有会话的差异设置继续生效，调整全局默认不会覆盖它们。

模型接口支持“获取模型列表”：填写基础地址（例如 `https://服务商/v1`）或完整聊天地址后，服务端读取对应的 `/models` 接口，再从列表选择模型；获取成功会补全聊天接口路径。服务商不提供列表时仍可填写完整聊天地址并手动输入模型 ID。读取列表只在点击时进行，不会发送试聊请求或保存草稿。密钥框留空保留现有值，输入内容则在保存时替换；清除已保存密钥有单独按钮，保存前可撤销。环境变量密钥仍优先于文件配置。

在「群与好友」查看当前登录账号的 QQ 群和好友，按名称、备注或号码搜索，逐项开启或关闭 Bot。采用**黑名单机制，默认全部开启**，新加入的群和好友同样默认开启；只有关闭的对象被拦截。群内 AI 聊天按真实 @ 或关键词触发，其他插件使用各自的命令或事件入口。开关立即保存到 SQLite，无须重新应用配置，并按机器人账号、群 / 私聊和对象号码隔离。关闭后停止该会话的新消息处理、记忆学习、回复与工具操作；已存历史和记忆保留，已经提交给 QQ 的网络请求无法撤回。重新开启不会恢复已失效的聊天回复或工具确认；已创建的提醒会暂停，开启后继续处理到期提醒。列表按需加载，可手动刷新；即使聊天服务尚未配置好，只要 QQ / Milky 已连接，仍可管理开关。

每行的「插件」按钮可分别关闭该群或好友的原生、NoneBot 插件，取消勾选即时生效，同样采用黑名单机制。全局启用项在「配置管理」勾选后保存并应用；戳一戳、轮盘禁言和六个 NoneBot 预设默认全局关闭。会话勾选不能启用一个全局已关闭的插件。

轮盘禁言、戳一戳等十二项原生功能直接由 Rust 运行，无需开启 NoneBot。启用 NoneBot 前需设置至少 32 字节的独立连接令牌；缺少令牌会阻止整份配置应用，旧运行实例保持原配置。管理页会持续区分「已保存待应用」与「已应用」，显示应用阻塞原因，以及各插件在当前运行实例中的实际启用状态。

也可手动编辑 `config.toml`，设置 `[milky]` 和 `[llm]` 后启动：

```powershell
$env:QKBOT_API_KEY = "你的模型密钥"
# $env:QKBOT_MILKY_TOKEN = "你的 Milky token"
.\target\release\qkbot.exe --config config.toml --check
.\target\release\qkbot.exe --config config.toml
```

Linux / macOS 使用 `cargo build --release --locked` 和 `./target/release/qkbot`。不需要 Node.js 运行机器人；Node 只用于可选的本地性能冒烟脚本。

`--check` 只校验配置，不连接 QQ 或模型。环境变量覆盖文件中的密钥；相对数据库路径按配置文件目录解析。日志输出到 stderr，可交给服务管理器轮转。退出使用 Ctrl+C，Unix 也处理 SIGTERM。

## QQ 扫码登录

使用同时支持 Milky 和登录管理接口的 **LLBot（LuckyLilliaBot）**。先按 [LLBot 官方说明](https://luckylillia.com/guide/config) 安装并完成所选运行模式的前置配置 / 授权。LLBot 是独立的 QQ 协议端，Rust 程序不包含 QQ 客户端或签名服务。

1. 在 LLBot 中启用 Milky HTTP / WebSocket 服务，常见地址为 `http://127.0.0.1:3010`。
2. 在本项目管理页填入 Milky 地址和访问令牌；QQ 登录管理填入 LLBot WebUI 地址（常见为 `http://127.0.0.1:3080`）及其 **WebUI 密码**，保存配置。
3. 在“QQ 登录”中获取二维码，用手机 QQ 扫码并确认。页面轮询登录状态，机器人自动等待并连接 Milky；二维码失效时手动刷新。

管理员密码、LLBot WebUI 密码、Milky 访问令牌和 LLBot 前置授权 `auth_token` 用途不同。这里代理二维码与登录状态，不收集 QQ 密码，也不管理签名授权。接口按 [LLBot v8.3.2 源码契约](https://github.com/LLOneBot/LuckyLilliaBot/blob/dc2b2b90092ef0f571b5546878288b83fff1e436/src/webui/BE/routes/login.ts) 实现；其他 Milky 协议端仍能接入聊天，内嵌扫码需要提供相应管理接口适配。

QQ 状态在服务端缓存 3 秒，同时到达的状态请求共用一次上游查询；二维码只允许一次在途获取。认证失败后暂停访问 LLBot，修改登录配置或明确手动重试后再尝试；临时网络故障由页面退避查询。改变配置会使旧请求结果失效。

配置页面不会返回已有密钥；分别选择保留、替换或清空。环境变量 `QKBOT_API_KEY`、`QKBOT_MILKY_TOKEN`、`QKBOT_LLBOT_TOKEN` 优先于文件配置，页面会标明来源，环境变量值不会写回配置文件。首次初始化码也可由至少 32 字节的 `QKBOT_ADMIN_TOKEN` 提供，设置密码后不再用于认证。保存配置使用同目录原子替换，并检测版本冲突；会规范化 TOML 格式，不保留原文件注释。后台读取已验证的内存快照；明确刷新配置时才重新读取外部编辑。

管理端默认仅监听本机。远程访问可使用 SSH 端口转发；需要公开服务时，将它放在 HTTPS 反向代理后并设置 `web.secure_cookie = true`。该开关明确控制 Cookie 的 `Secure` 属性，不根据请求头猜测。`web.enabled`、`web.listen`、`web.secure_cookie` 和日志过滤级别需要重启整个程序；数据库路径 `app.database` 与数据库队列容量 `limits.database_queue` 也必须重启才能应用。其他配置可在页面保存后应用。`web.enabled = false` 可关闭管理页。

## 配置取舍

`[plugins.ai.defaults]` 是全局默认，“会话”页面保存各会话的差异设置。工具能力及部署级队列和调用配额在管理页或配置文件中调整，保存并应用后生效；数据库队列容量需要重启程序。

`reply_to_bot = true` 默认开启“回复机器人消息时触发 AI”：在群内引用回复当前机器人账号发出的消息，无需再次 @ 或输入关键词。管理页的全局配置和会话设置均可调整；关闭后仍保留私聊、@ 和关键词触发。原生插件命令与 NoneBot 已接管的交互优先处理；引用其他成员、转发内部的引用或机器人自身事件不会因此触发。

引用目标按机器人账号、聊天类型、群／好友和消息序号确认，优先使用本地记录，缺失时最多并发两次、每次两秒向 Milky 补查。查询失败或繁忙时不增加触发，原有 @ 等触发仍有效；同会话的后续消息按顺序处理。引用仅附加该条消息的至多 1000 字文字，不恢复旧会话、不切换到原提问者的记忆，也不将机器人内容作为当前用户的事实证据；已遗忘来源不会重新注入，图片等无文字内容会明确标记为不可读。

允许模型使用的工具从实际注册表自动载入，以勾选列表配置，无须手写工具名；列表显示说明、所属插件与操作类型。全局勾选并启用对应插件、保存并应用后生效；会话只能进一步缩小允许范围，取消全部勾选即禁用全部模型工具。升级后失效的已选工具会保留显示，便于取消和修复配置。

人设在配置页和会话页直接从列表选择。内置五套成年男性角色：**雄小鬼**（默认，爱斗嘴、好胜、嘴硬心软）、清朗青年（坦率有活力）、温柔学长（耐心有分寸）、理性搭档（简洁、冷幽默）、沉稳前辈（务实、松弛）。配置页可预览完整模板，编辑或另存自定义人设，无须填写 JSON；同名自定义内容优先于内置模板。全局配置保存并应用后生效，会话选择单独保存；切换人设保留历史和记忆。

在“记忆与上下文”页选择已保存、已应用的人设，点击“应用到全部群聊”，确认账号与群数量后立即生效。后台以提交时刷新得到的 QQ 群列表为准，一次更新该账号全部现有群的共享及成员隔离会话，同时保存这些群以后新建会话的人设。好友、其他账号及全局默认不变；之后新加入的群仍使用全局默认。各会话的其他设置、历史、摘要和长期记忆保留，旧人设未完成的回复取消。操作按请求编号去重，网络中断后可查询结果；仍可在会话页单独切换某个会话。

提示词结构参考 [dafeiyu-bot 的 QQPersona / QQPersonality](https://github.com/SAKURAfan1023/dafeiyu-bot/blob/282f7d0c7444d2c6ef4f03a5a77e72862c844f27/Sources/BotCore/QQPersona.swift)，模板正文为小鱼原创：宿主身份、权限和能力规则 → 本轮选定的角色与表达习惯 → 真实会话上下文。历史中的旧性格不覆盖当前选择；人设不会改变工具权限、事实归属或上下文隔离。每轮只注入当前一套模板，不增加模型调用或外部依赖。

`mode` 是新群的初始模式；已有群在“会话”页面切换模式，避免修改默认值时意外恢复旧会话。关闭记忆写入或暂停期间的新消息不会被标记为自动学习来源。

群聊发言会保存消息当时的群名片和 QQ 昵称，模型优先用群名片称呼用户，缺失时回退到昵称或 QQ 号。名称只作显示，身份、权限、记忆和证据仍绑定 QQ 号；同名、改名及跨群名片不会合并用户。名称来自事件自带的成员信息，不额外拉取成员目录；老消息无需补查，原始正文保持不变。

升级时若配置仍包含旧 `[access]` 白名单，程序会拒绝加载，避免无提示扩大聊天范围。请先核对黑名单、明确接受“未关闭的会话默认开启”后，再手动移除旧配置段；正常黑名单配置不受影响。

| 默认项 | 值 |
| --- | ---: |
| 模型 HTTP 并发 / 后台整理并发 | 2 / 1 |
| 全局 / 每会话待处理聊天 | 32 / 4 |
| 输入估算预算 / 输出上限 | 6000 / 800 |
| 近期消息 | 24 条 |
| 注入长期记忆 | 默认至多 5 条、1000 估算 tokens，可配置 |
| 每会话长期记忆容量 | 默认 256 条，可配置 |
| 单轮模型请求 / 工具调用 | 至多 3 / 2 |
| 单次模型 / 工具 / 整轮期限 | 60 / 15 / 120 秒 |
| 每会话发送额度 / AI 冷却 | 每小时 120 条 / 2 秒 |
| 普通消息保留期 | 7 天 |

预算使用保守的 UTF-8 字节估算，**不是模型 tokenizer 的精确计数**。工具定义、调用和结果都计入输入预算；问题本身超限会明确拒绝。普通聊天通常只请求模型一次，当前无隐藏重试。

`max_memories_per_conversation` 控制磁盘中的长期记忆容量；`memory_recall_limit` / `memory_recall_budget` 控制一次取回多少内容，提高容量不会把全部记忆装进上下文。降低容量不会删除既有记忆。输入预算可调至 262144、输出上限至 32768、历史至 4096 条；实际可用量仍取决于所选模型、消息发送限制与总输入预算。复杂工具任务可提高 `max_model_calls`、`max_tool_calls`、`max_http_attempts` 和整轮超时，保留有界执行及最终回答机会。

关键词检索是首版的低占用选择，换一种完全不同的说法可能漏召回。先收集真实漏召回案例，再决定是否加向量检索。群内 `user` 模式只隔离上下文，回复仍发到群里。

## 引用与 @ 回复

`reply_message` 让模型把引用、@ 和正文合并为本轮唯一的最终回复，例如引用某条可见消息回答问题，同时 @ 相关成员。每条回复最多引用一条消息；@ 去重后最多三人，仅限群聊。普通回应仍可直接输出文字；本轮回复不额外请求确认，提醒创建、取消等业务写工具仍执行原有确认流程。

新配置默认允许 `reply_message`，管理页将其显示为 AI 插件的“本轮回复”工具。已有配置若显式填写了 `allowed_tools`，升级不会自动扩大名单：管理员需在全局工具列表勾选并保存、应用；继承全局设置的会话随后可使用，已有显式会话名单仍须按需勾选。模型接口还需开启原生工具调用。

宿主只为本轮实际可见的当前消息、近期上下文、当前明确引用的消息，以及这些来源中的发言者和当前消息真实 @ 的对象提供引用标识。模型不能用正文中的昵称或 QQ 号自行指定目标，也不能跨机器人账号、群／私聊或逻辑会话查找历史；当前明确引用按当前聊天验证后可使用。已遗忘、因预算裁剪而未向本轮模型提供或其他已失效的目标不能用于引用或 @。首版不提供 `get_recent_messages`、`get_message` 或 `find_member` 工具来查询新目标。

当前机器人发送给模型的输入仍只有文字，尚未接入视觉输入链路；选择支持识图的模型接口不会自动让机器人读取收到或被引用图片的内容。

## 会话与记忆管理

“会话”页面按机器人、群或好友、用户和模式筛选，查看摘要和上下文数量，调整人设、预算、历史长度、工具、记忆读写和摘要开关，也可暂停、恢复或放行一次触发。重置会清空活跃上下文与摘要，保留长期记忆；切换群模式创建隔离的新会话版本。

“记忆”页面支持分页检索、查看证据与关联原文、人工新增和编辑、启用或停用。人工记录默认锁定，自动整理不会改写人工或锁定记录。停用和到期只排除召回，保留记录及来源，也继续计入存储容量。

从机器人记忆中遗忘使用“预览影响 → 确认”流程，可单条或批量操作。预览包含受共同来源影响的派生记忆；确认后撤销相关历史来源，清空受影响会话的摘要与活跃上下文，防止旧任务重新学回。本地原始消息按保留期清理，遗忘不等同于立即擦除原文，也不会删除 QQ 消息、远端模型记录或备份。此操作需要重新验证密码，确认凭据与当前管理员会话绑定，5 分钟有效。写操作带幂等请求 ID，超时后可以查询已有结果。

关闭自动记忆写入不影响人工维护；摘要也有独立开关。关闭摘要同时停止生成和注入，近期上下文按历史长度读取原始消息，长期事实仍可独立学习。再次开启时，从仍保留的原文补齐摘要进度，不重复提取已处理事实。

空闲会话即使只有少量消息，也会尝试从符合学习条件的完整消息中提炼长期事实，不必等待近期上下文被压缩。整理仍受后台并发和每小时调用额度约束，按会话轮转并对失败退避；一个异常会话不会堵住其他会话。自动提炼是后台工作，聊天中说“记住”不代表已经可靠写入，可在记忆页核对或人工保存。新摘要按下一轮输入预算限制长度；旧摘要过长时有界分段再整理，完成校验后才替换原摘要。

后台提炼和旧摘要修复均接受裸 JSON 或完整单个 JSON 代码块；代码块只去掉外层包装，内部字段、人物身份和原文证据仍严格校验。截断响应、混入解释、多个代码块或无效证据不会被自动补全或部分保存，失败批次也不会推进处理游标。解析错误日志只记录类型与位置，不包含模型返回正文；模型调用计数增加不等于已写入，确认结果应查看自动记忆及其来源证据。

## 聊天指令

```text
/bot confirm TOKEN
/bot reject TOKEN

/clock
/remind add 600 喝水
/remind list
/remind cancel ID
```

提醒插件默认关闭。启用 `[plugins.reminder].enabled` 后，普通 `/remind` 指令直接执行业务；若要让模型使用，还需把 `reminder_list`、`reminder_create`、`reminder_cancel` 加入 AI 的 `allowed_tools`。模型写操作等待本人在原聊天发送 `/bot confirm TOKEN`；5 分钟内有效，时间和内容已固定。等待确认不阻塞聊天，也不会再调用模型决定是否执行。

已创建的提醒可跨重启保留，未确认的请求在重启后失效。收到离线或换号事件后，暂停新发送与引用读取；原账号重新验证成功后，确定尚未提交的提醒恢复待发送，发送结果未知的提醒仍不自动重发。

到期领取与异常恢复均只处理当前已验证账号的提醒，每次领取一条并关联发送账本；数据库回写中断后，可区分尚未提交、确定完成和结果未知。其他账号的待办保持等待，不会被当前账号消耗。联系人列表暂不可用时，页面保留上次读取的账号列表供关闭 Bot，开启仍须恢复连接后重新核验；旧协议缺少群备注字段时显示为空。

## 扩展插件

在 `src/plugins/` 编写 `Plugin` 实现，在 `plugins/mod.rs` 显式装配。普通命令与模型工具复用业务方法；要提供给模型，实现 `Tool` 并注册，还须配置工具允许列表。新增工具无需修改 AI 主循环。`Plugin::accepts` 管命令和事件范围，`Tool::permits` 独立约束工具范围；本地 Rust 插件属于可信代码。

数据库迁移使用 `Store::migrate(plugin_id, version, sql)`，按插件记录校验和。数据库由专用线程持有；事务内只做短小的本地工作。所有发送使用 `Host::send`，网络结果未知时记账，不自动重发。

详细说明见 [架构与边界](architecture.md)。
